# 手机 MCP 平台技能使用指南

“紫薇·互联手机操控”是平台技能目录中的正式技能，目录标识为 `ziwei-phone-control`，当前版本为 **1.0.0**。它把员工的工作区、运行电脑、Codex/Hermes 配置和一台真实手机绑定起来，通过 `ziwei-terminal` MCP 使用原手机中控的工具与命令回执。

使用入口为 [紫薇平台](https://qzelynth.top)。普通配置在页面内完成，无需填写管理员密码、手机角色 token、API Key，无需手改 TOML/JSON 或在终端粘贴密钥。技能安装、配置保存、API 可达、MCP 加载、手机命令成功和业务目标达成分别判断。

## 打开统一配置向导

以下三组入口打开同一个“手机技能配置”向导，保存结果共享：

| 入口 | 操作 |
| --- | --- |
| 技能中心 | 打开“平台技能”，找到“紫薇·互联手机操控”，点击“安装并配置”或“配置手机技能”。技能卡片提供实际版本与安装状态。 |
| 数字员工详情 | 在员工的“技能”页或“MCP”页点击“配置手机技能”，向导预选该员工。 |
| 紫薇·互联手机绑定 | 在目标手机的员工绑定区域点击“配置手机技能”，继续选择员工及运行环境。 |

保存配置需要当前工作区 Owner 或 Admin 权限。只读查看不会自动修改员工或手机。先确认页面上方的当前工作区，手机专用员工应配置在其实际所属工作区，例如 `phone_ai`。

## 配置已有员工或创建新员工

1. 在向导“工作区与员工”中明确选择工作区和数字员工。已有员工可以直接继续配置。
2. 需要新员工时点击“创建新员工”，使用现有员工创建表单填写名称、岗位说明、人格与协作方式，选择目标电脑、运行时及模型。保留“保存后配置手机技能”，创建成功后自动返回手机配置向导。
3. 选择当前工作区中实际在线的目标电脑。电脑、CLI 和 profile 来自本机客户端真实心跳；看到电脑名称或保存了授权不等于该电脑已经就绪。
4. 选择运行时和运行配置。当前手机 MCP 适配 **Codex 和 Hermes**，不会把其他 CLI 静默替换成其中一种。
5. 选择“绑定手机”，核对手机显示名及向导展示的完整手机 ID。外部账号 ID、账号显示名为可选信息，未选择具体账号时可以留空。
6. 保持“启用手机 MCP”并点击“保存安全配置”。平台安装目录技能、挂载到员工，并原子保存运行环境与精确手机绑定；页面随后回读实际保存结果。

Codex 可明确选择“默认 CLI 配置”，也可选择目标电脑已发现的独立配置。Hermes 必须选择独立 profile，不能使用 `default` 或回退主 profile。新建 Hermes 员工时，可在原员工表单填写独立 profile 名称，点击“在此设备创建 Profile”，等待电脑回执与就绪状态后继续。已有目录不等于 provider 已通过校验；以表单的就绪提示为准。

配置只向所选员工提供所绑定手机的能力，不会广播到其他手机。更换电脑、运行时、profile、手机、技能版本或影响绑定的配置后，需要重新检测该配置；旧执行的回执不能验证新目标。

## 让已有电脑明确连接另一个工作区

如果电脑目前只连接 `test_222`，在 `phone_ai` 中没有可用的同一台电脑，可以展开“授权已有电脑连接当前工作区”：

1. 当前登录者须同时拥有来源工作区与目标工作区的 Owner 权限。
2. 明确选择来源工作区及其中在线的来源电脑，点击“授权此电脑连接当前工作区”。
3. 等待客户端领取授权并向目标工作区报告真实心跳。向导会区分“授权已保存”“授权已领取，等待电脑真正连接”与“当前工作区已收到此电脑真实心跳”。
4. 在目标电脑列表中选择新工作区实际发现的连接，再选择运行时和 profile。

这是同一客户端的独立工作区连接。来源工作区保留原连接及独立凭据，目标工作区使用新凭据和身份；主工作区 token 不能跨工作区使用。无需另开业务 daemon、改本机端口或复制配置文件。重复操作应读取原授权状态，不能用名称相同的未认证默认电脑代替已经授权的目标。

如果目标电脑提示“尚未报告当前工作区的手机 MCP 适配”，需让原本机客户端具备当前版本的适配并等待心跳；不能只把页面上的电脑状态改成在线来跳过检查。

## 检测实际 MCP，再验证手机

配置保存后，点击“检测 MCP 加载”。平台会建立该员工的真实持久会话，在明确选择的电脑和运行配置中初始化 MCP，并实际调用设备列表及状态工具。该次检测仅允许只读发现，不下发手机命令；手机离线时仍可验证 MCP 连接及读取到的离线状态。

在“MCP 加载回执”中核对实际加载与工具调用结果。平台显示“已注入”时，仅表示运行配置已交给 CLI；只有真实初始化和工具加载回执支持“已实际加载”。检测 API 返回了 action ID 或会话已创建，同样不等于检测已经完成。

手机在线且实际 MCP 已加载后，可以勾选“允许在所选手机执行只读健康检查”，再点击“只读试运行”。当前页面试运行只对绑定手机提交一次健康检查，并等待原命令回执。该勾选用于明确本次试运行范围，正常员工任务沿用用户已经给出的授权，不要求每次点击重复审批。

等待期间查看向导展示的原动作 ID。读取中断或超过页面等待时限时，点击“继续读取本次回执”或刷新配置状态，先回读原动作；不要把重复试运行作为查询状态的方法。服务端按幂等键区分重复请求与新的配置，提交结果不确定时应继续核验原请求。

正式任务从员工“打开持久会话”继续。先让员工列出并核对绑定手机、读取健康，再根据用户已授权的具体任务操作。截图、动作、回执与新的截图应串联核验；一次健康检查通过只证明当次手机命令链路成功。

## 如何理解状态与证据

向导同时显示“保存与技能”“手机控制 API”“真实设备发现”“MCP 加载回执”和“实机命令回执”。页面顶部为当前主要阻碍或进度；例如手机离线时会优先显示“等待手机”，下面仍保留独立的 MCP 加载证据。

| 状态或证据 | 含义及下一步 |
| --- | --- |
| 未配置 | 尚未保存有效且启用的员工手机配置，或技能未安装、未挂载。先完成选择并保存。 |
| 配置有改动，待保存 | 页面选择与已保存配置不同。先保存，不能使用旧回执证明新配置。 |
| 等待电脑 / 等待电脑配置 | 所选电脑未在当前工作区报告健康心跳，或 CLI、profile、手机 MCP 适配未就绪。核对原客户端和精确电脑。 |
| 等待手机 | 精确绑定手机的当前控制端未在线、控制权未就绪或正在切换。恢复这台手机后刷新，不切换其他手机补验。 |
| 认证失败 | 实际连接认证未通过。由管理员检查平台与电脑安全连接；不要将密码或 token 填入员工提示词。 |
| API 不可用 | 原手机中控连接不可达。先排查 API，不能把已保存配置当成当前连接正常。 |
| 已保存，待检测 / 等待加载回执 | 保存已完成，或执行已派发、配置已注入，但仍缺少实际 MCP 加载证据。 |
| MCP 已加载 | 取得实际加载回执；本次配置尚未取得真实手机命令成功证据。 |
| 等待实机回执 / 实机结果待核验 | 已提交原命令，但仍在执行或结果不确定。读取原 command ID，不能盲目重放。 |
| 实机通过 | 当前配置、当前执行、精确手机的真实命令成功，且实际 MCP 已加载。截图试运行还必须具备实际图片证据。它不自动证明某个业务任务已完成。 |
| `never_run` / 尚无真实命令 | 该阶段尚无对应执行或命令证据，不是成功。 |

手机命令的 `queued`、`delivered`、`executing` 均为进行中；`succeeded` 才是手机命令成功回执。`failed`、`expired`、`uncertain` 应按真实状态报告。升级事务的 `planned`、`installing`、`awaiting_health` 不是完成，`committed` 才表示事务提交成功，`awaiting_user_action` 需要手机上的真实系统确认。

截图命令成功但没有实际图片时，平台不会将该截图验收标为成功。使用截图必须保留本次画面与原始尺寸，不能用历史图片推断当前界面。命令成功也需结合实际新画面和任务要求确认业务结果，例如“已打开目标页面”与“已完成运营任务”是不同结论。

## 员工的十项手机工具

正式员工执行提供完整十项工具，仍受当前工作区、员工、电脑、profile、配置修订、执行和绑定手机的精确范围约束。

| 工具 | 能力与使用边界 |
| --- | --- |
| `ziwei_phone_list` | 只读列出当前员工明确绑定的手机及其 Agent/Updater 状态，不列出可随意操作的全平台设备。 |
| `ziwei_phone_status` | 只读获取指定手机健康、控制权、在途命令和活动升级事务，不下发新动作、不返回历史截图。 |
| `ziwei_phone_receipt` | 使用原 `deviceId`、`commandId` 查询命令状态、错误和回执元数据，不重发原命令。 |
| `ziwei_phone_action` | 健康检查、截图、点击、滑动、文字输入、返回/主页/多任务、打开应用。坐标操作须依据本次截图原始尺寸。 |
| `ziwei_phone_screenshot` | 请求并读取手机当前截图，通过 MCP 图片内容返回本次画面。 |
| `ziwei_phone_control` | 切换 Agent/Updater 控制角色或暂停控制，沿用原中控审计；这是修改操作。 |
| `ziwei_phone_upgrade` | 沿用原发布索引、截图前置检查和升级事务。仅在用户实际要求升级时执行，不作为连接检测。 |
| `ziwei_phone_wait` | 等待原命令或升级事务的终态；超时返回当前状态，不重新提交动作。 |
| `ziwei_enrollment_pending` | 查看当前授权范围内与所选手机精确对应的待审核入网申请。 |
| `ziwei_enrollment_approve` | 批准精确匹配所选目标的一条申请，沿用原 Agent/Updater 配对机制；不批量批准未知设备。 |

完整工具能力不代表用户已授权发送消息、发布内容、点赞、关注、改变账号或系统设置。员工按用户任务执行，已有授权持续有效；缺少目标或操作范围时只补问必要信息，不人为限制为某个岗位白名单，也不以 shell、SSH、ADB 或数据库绕过手机 MCP。

## 认证与运行边界

- 原手机中控继续管理手机入网、状态、命令队列、升级事务及管理员/手机角色凭据。平台复用现有连接、员工绑定和运行记录，不另建手机控制队列。
- 员工执行前，所选电脑使用当前工作区的独立设备身份换取短期、限定本次执行的 capability。员工 MCP 只读取其私有 capability 文件；原管理员密码、Android 角色 token 和管理 MCP bearer 不分发到前端、员工提示词或技能文本。
- 服务端在每次调用时重新核对员工、工作区、电脑、运行配置、精确手机、当前配置修订和活动执行。过期、撤销、作用域不符或配置已经改变时拒绝调用，不能回退其他手机、profile 或工作区。
- 技能安装状态、员工启用状态、管理 MCP 配置与手机 MCP 配置分别生效。关闭手机 MCP 或卸载技能不等于删除员工人格及其他技能，也不等于注销真实手机。
- 诊断材料只应记录必要的对象 ID、状态、错误码和回执时间。不要提交私有文件、原 token、管理员登录文件、截图中的账号信息或完整业务内容到 Git、公共报告或提示词。

已获得明确工作区管理能力的员工搭建师，也可通过管理 MCP 发现技能、安装目录技能、创建员工、配置精确手机并回读状态。跨工作区时必须显式选择目标 `workspace`，且管理 bearer 先有该工作区授权；填写参数不能扩展 bearer 权限。对应管理工具为 `ziwei_phone_mcp_setup`、`ziwei_install_skill`、`ziwei_configure_phone_mcp`、`ziwei_get_phone_mcp_status`、`ziwei_check_phone_mcp` 和 `ziwei_trial_phone_mcp`，它们不替代上述十项员工手机工具。
