# Bot 停止与原执行回执恢复修复

本次修复针对已领取的执行过期后仍占用 Bot、停止请求未派发，以及继承模型配置检查回执被误拒收的问题。无需修改数据库结构，保留员工、Profile、HOME、主聊天和原动作 ID。

- 过期或待核实动作可以下发取消；取消使用客户端独立控制通道，不受普通执行并发或隔离状态阻塞。
- 已有完整退出证明可补传原结果；过期 ACK 不授予重新执行权限。迟到证明须等待执行器清理完成，才可结算并解除占用。
- 服务器保存的原终态事件可通过 Bot 运行记录或主聊天的“核实并恢复回执”操作恢复。接口只接受原事件 ID 和当前版本，校验动作、设备、员工及 Profile 绑定。
- 继承模型使用设备验证得到的有效模型校验推理证明；显式指定的模型仍严格校验。
- 恢复保留过期审计，不重新派协作任务、自动重试或发送 webhook。恢复旧版本的配置检查不会启用 Bot，也不会将旧控制版本标为当前验证成功。

缺少可信进程退出证据时仍显示待核实；客户端没有内存控制器不等于进程已经退出。旧 Windows 客户端须更新才具备独立停止通道与迟到证明补传能力。不能通过删除旧动作、清占用字段或重新建 Bot 来冒充恢复。

发布顺序：通过相关回归、构建与离线安装检查，提交并正常推送 `codex/v2-20261014-release`，确认远端提交，再上传对应源码和客户端包、备份当前数据库、切换 API 与静态资源、发布客户端元数据并逐项读回。此次不变更 Nginx、手机控制服务或数据库结构。失败时恢复上一 V2 代码及客户端发布元数据，继续使用当前数据库，不整体恢复旧数据库。

测试覆盖包含真实 repository 与持久客户端投递层的无网络协议联调：原结果上传中断、原动作过期、请求停止、核实原退出证明、清除占用，并确认执行次数仍为一次。这是协议回归，不冒充 Windows 实机或模型 provider 实测。
