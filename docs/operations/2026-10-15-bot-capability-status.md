# Bot 能力状态与直接配置

能力组合原先把接口接入程度和实际运行状态混在一起，大多数卡片只重复“以实际回执为准”。本次由后端根据保存的配置、运行电脑、当前配置检查和各项原生操作生成能力状态，并提供对应的下一步操作。

## 状态依据

- 保留原有 `status` 字段兼容旧调用方；新增 `state`、`enabled`、`reason`、`action`、`checkedAt`，页面显示具体状态。
- `capabilityGate` 集中显示电脑离线、Profile 创建、认证、配置检查和 Bot 启用等共同前置条件。单项能力说明负责指出对应缺项。
- 配置已开启与实际检查通过分别显示。模型继承来源 Profile 不会因为员工的模型字段为空而被误判为未配置。
- 原生结果必须匹配员工、工作区、设备及当前配置和控制版本；旧结果、失败结果和合成结果不能证明当前能力可用。渠道配置读回不能证明连接在线，语音配置读回不能证明音频调用成功。
- Profile、HOME、原始执行标识和其他诊断依据默认折叠。具体故障和配置入口继续直接显示。

## 开启按钮

长期记忆、工具权限及满足前置条件的伙伴协作可直接开启。工具授权按钮明确显示“允许使用工具”；开启记忆不会顺带提高工具权限。需要账号、服务地址、伙伴或计划的能力跳转到对应设置区域。

直接开启执行“保存、读回、无模型配置检查”。仅点击前已经启用的 Bot，在保存版本及控制版本均保持一致、检查成功后恢复工作。原本暂停或草稿状态的 Bot 不会自动启用。存在未保存草稿、并发修改、导航切换、检查失败或结果未知时，不覆盖草稿或宣称启用成功。

## 验证与发布

后端状态推导和前端开启流程使用内存测试。`frontend/verification/bot-capability-browser-fixture.mjs` 使用实际构建页面和实际内存管理服务，由 Playwright 拦截所有请求；设备发现、Profile 创建及配置检查结果为显式合成数据，不连接真实电脑或模型，也不启动本地监听服务。

发布前验证：12 项能力状态测试、35 项既有 Bot/原生操作回归、206 项前端测试通过；浏览器 7 项场景通过，1440px 和 390px 无水平溢出，未发现页面异常或意外请求。前端构建、141 个源文件检查和差异格式检查通过。需启动随机监听端口的另一个历史 HTTP 测试未运行，本次交互由无监听浏览器集成覆盖。

发布顺序为提交并推送 GitHub、打包已提交版本、验证离线安装、备份服务器数据库、切换 API 和静态页面、核对公开资源与提交标识。此次不迁移数据库结构，不改变现有 Bot 的配置或启用状态。回退时切回上一版代码并保留当前数据。
