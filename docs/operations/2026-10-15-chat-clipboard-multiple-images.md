# 聊天粘贴图片与 Hermes 多图输入

Bot 主聊天及普通数字员工聊天支持从剪贴板粘贴图片。可以一次粘贴多张，也可以连续粘贴后一起发送；保留已有文字、图片预览、删除和重新编辑。普通文字仍使用浏览器原有粘贴行为，不抓取剪贴板 HTML 中的远程图片。

每条消息最多 20 张，图片总大小最多 10 MiB，支持 PNG、JPEG、GIF、WebP。读取或发送期间不会覆盖附件；切换工作区、员工或会话后，旧的异步图片读取不会写入新草稿。

Hermes 底层原生视觉消息支持多个图片内容块，但已安装 CLI 的 `--image` 为单值参数。现在多图走执行内兼容层：从已校验的本机附件生成受控列表，在原生 Profile 与查询读取完成后调用原生图片组装函数，将全部图片按顺序放入同一条用户消息。检查图片数量、原始字节和顺序；缺图、丢图或模型仅支持文字时明确失败。单图和无图保留原入口，不改已安装的 Hermes 源文件。

目标 provider 是现有 Codex 订阅及其视觉模型。某些本地 provider 会转码图片；本次要求保留原始字节，因此这种多图输入会明确拒绝，不能视为所有 provider 都已验证。

## 验证

- 前端 226 项测试通过。真实 Vue 浏览器测试 7 项通过：Bot 一次粘贴两图、继续追加、删除中间图片再追加，单次发送三张不同原图；普通员工发送两图。核对单条消息、同一执行动作中的原始字节与顺序，无浏览器错误或意外外部请求。
- 新增运行时回归覆盖同条原生视觉消息、受控图片清单、数量和顺序、缺图或改字节、非视觉模型、原生丢图或文字退化、源码兼容绑定、临时 overlay 清理以及源 Profile/auth 保留。
- 本机已安装 Hermes 的多图源码绑定检查及原生图片组装函数测试通过。以上运行时测试不调用真实模型，Windows 专用测试在 Mac 不作为通过证据。

## 发布与实际使用

先提交并推送 GitHub，再从同一提交打包网页、服务端和 Windows 客户端。部署前备份数据库，保留上一版代码供回退，不修改数据库结构。

多图要求 Windows 客户端更新，旧客户端仍有单图限制。用户已确认发布后会在外部终端执行 `ziwei_user update`，随后执行 `ziwei_user update-status` 确认完成。不要让 Bot 从自己正在运行的执行树中更新自身客户端。

更新完成后，用真实已登录的 Bot 主聊天发送两张内容不同的图片，要求逐张描述，以此完成 Windows、真实 provider 与聊天消息保存的最终验收。在此之前，不能把本次多图标记为 Windows 真模型实测通过。
