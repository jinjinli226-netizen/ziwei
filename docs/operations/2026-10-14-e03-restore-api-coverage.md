# Restore API coverage boundary

The old source observation copied request DB/fence/build pins into every restored host's runningV2, including client-only Windows hosts. The old product validator required those labels on each host and made runtime identity proof verification conditional on declaring a runtime evidence directory. Consequently an authenticated client host could appear to report API sealed state without an actual API identity, and a proof that omitted the directory could avoid the private API proof check.

The source ABI now reports only productRole/instances on client-only hosts. DB/fence/build fields come only from a verified local API identity payload. The product adapter permits that honest client-only shape and rejects client-supplied API labels with PRODUCTION_RESTORE_CLIENT_API_CLAIM. Every restored host with expected instances must provide exactly one approved runtime capture; declaring no runtime evidence directory no longer bypasses this requirement.

Restore aggregation must have at least one approved API target. It verifies every expected API target's actual private API identity through its approved host key, fresh challenge, operation/spec/freeze, original binding, target/build/source/nonce and same physical main DB/sealed control state. API observation fields must agree with the private identity, and the complete expected host/target set must be covered exactly once. Missing API coverage fails PRODUCTION_RESTORE_API_REQUIRED. Client-only source proofs still cannot authorize a full production restore.

The export of the existing verifySourceProofs function enables direct pure aggregate regression tests; the production caller still creates and validates its own request set from the approved spec, independent trust and live same-DB control state. The tests are cryptographic/schema fixtures, distinct from native service qualification. They use the actual private identity factories with code-only startup IO seams over real isolated SQLite/config bytes. No formal service or database is touched.

Dedicated tests accept an independently signed actual API identity plus honest client-only observation, and reject missing API/directory, client-only full restore, client DB claims, wrong DB/fence/target/challenge/nonce and cross-host borrowed API signer. Existing lifecycle tests now supply private API identity evidence instead of synthetic running labels, retaining their same-currentDB compatibility increments/tombstones and distinct physical release checks. Every host's action/key/scope binding and the global debt checks remain unchanged.

This is a separately authorized finite adapter correction. E02/R must integrate it together with the E03 client/native source ABI. Formal production clearance still depends on genuine source captures; the original Windows SDK's unrecorded discovery descendant history remains unresolved.
