Actual isolated daemon testing exposed a normal shutdown lifecycle defect. The old `health.close` callback immediately forced `process.exit(0)`. Two retained runs logged JS exit code zero and then an external Windows libuv assertion/OS exit 3221226505. JS exit logging therefore did not prove successful process termination. The exact native handle was not identified; no claim of a Node/libuv internals fix is made.

Normal shutdown now blocks new heartbeats, cancels and joins registered prepare/heartbeat/register requests, aborts existing polls, and prevents startup heartbeat continuation from restoring timers. It consumes register bodies and uses natural event-loop exit. The exit event only appends the business log synchronously. The independent observer preserves the external exit code and waits for stdio close before completing its receipt. Action ACK/result/execution cancellation was not added; existing local maintenance safety checks remain in place.
