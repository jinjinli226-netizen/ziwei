# 指定原结果补交

服务器拒收后，已结束的 action/result 会保存在设备的 `archived_unconfirmed` 投递记录中。修复服务器上传限制不会自动补交这些记录。使用原设备上运行中的 daemon 补交指定结果：

```sh
ziwei_user delivery retry --action action_<原动作ID> --workspace <原工作区> --json
```

CLI 核对当前配置、设备、客户端构建和 daemon 实例，再通过本机认证入口请求原记录的持有者。daemon 校验 action/result 的身份、绑定、摘要和执行树退出证据，只发送既有 ACK（`receiptOnly:true, renewLease:true`）及原结果。结果上传沿用 600 秒预算和 Bot secret 协议，不调用执行器。

确认必须来自同一个 action 和设备，包含匹配的终态、完成时间及原图片的名称、类型、大小和 SHA-256。只收到成功事件或不含原图的终态回执仍会拒绝确认。成功后调用既有确认逻辑，保留原拒收归档和原始文件；有效的已确认归档不会重新进入自动恢复，也不继续阻塞维护。同一动作的并发请求共享一次补交，已确认后的重复请求不再上传。

缺少原结果、摘要不符、设备不符、进程尚未确定退出或服务器未确认时，命令失败并保留证据。应核对原 action 与诊断信息，修复实际原因后再用同一个动作 ID 补交。
