> **执行方式：** E03 可见会话继续实施与验证；内部代理仅做只读审查，不替代实现会话。用户已授权继续开发，不重复设计确认。

**目标：** 将原生记忆、技能、MCP、协作、Gateway、音频与主动工作能力接成紫薇可设置、可使用的真实操作流程，保留同一员工/主聊天/权限。

**技术栈：** Vue 3、现有紫薇组件与浅色样式、Node test、Playwright headless、本机隔离 SQLite/API；不使用 computer-use。

## 实施与验证顺序

1. `frontend/src/bot-native-operations.js` 与对应测试：先写作用域切换、旧读回、未知写入、同key恢复、异步action回执测试，再实现传输无关控制器。读取失败不谎称写入未知；不同资源操作相互隔离；暂停/状态不确定保留原执行证据。
2. `frontend/src/components/BotKnowledgePanel.vue`：原生记忆文档读取/编辑/删除与会话检索；技能目录/Hub查询、安装/更新/启停；HTTP/stdio MCP配置编辑，密钥仅引用本机变量名。覆盖修改冲突、草稿保存、作用域切换和操作回执。
3. `BotCollaborationPanel.vue`：同工作区目标Bot列表、群组与@、消息/委派、协作进度和父子执行归属。禁止跨工作区或自行回退到广播目标；失败与不确定不可盲目发新意图。
4. `BotChannelsPanel.vue`：Gateway平台/授权/路由/启动状态与错误；STT/TTS/音频和多模态输入输出；文件传输与录音只在用户明确使用该功能后发生。授权状态、配置已保存、实际连接及发送结果分别呈现。
5. `BotProactivePanel.vue`：Goals、Heartbeat、Kanban真实列表/编辑/启停/结果，显示原生调度与紫薇Routine的权威及兼容限制，不启动第二套重复调度。
6. E02增量合同到达后修改 `frontend/src/api.js` 与内部适配器；接受目录检查、原子初始化、真实Hermes/local test provider/fixture证据。前端只使用已存在的字段与端点；临时UI内部模型不自行定义服务器契约。
7. 组件浏览器验证、真实HTTP集成与原生证据核对；稳定提交后在精确拥有的本地预览更新，保留用户本地预览数据。接口未到时持续实现独立组件与行为，不宣布全量完成。

## 需要E02提供的稳定契约

以下是前端功能依赖，不是新造的HTTP接口：

- 各原生资源的读取/更新形态、revision/ETag、action创建与查询、操作幂等及取消/不确定恢复方式。
- 记忆文档标识、内容与版本，会话搜索/历史定位；技能目录/Hub结果、安装/更新/启停回执。
- HTTP/stdio MCP实际配置字段、secret引用、状态/错误和实际工具调用证据。
- 群组、@、消息/委派目标、父子action及结果归属、同工作区权限门。
- Gateway配置/授权状态/平台路由/连接与停止；音频设置、上传格式、STT/TTS动作与结果文件。
- Goals、Heartbeat、Kanban数据、状态、控制动作、调度唯一权威和对Routine的兼容规则。
- 原生Hermes可用性/版本、实际profile/device/执行证据来源，目录检查和初始化原子校验增量。

每个批次记录真实通过证据与尚需接入的依赖；仅阶段完成，全量目标继续。
