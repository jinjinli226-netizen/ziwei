# 紫薇·互联完整终端管理接入

状态：implemented（实施中；发布与浏览器证据完成后更新）。

- 目标：使用主站同一登录，在 `/<slug>/ziwei-connect` 审批手机入网，并使用原终端控制台的列表、详情、双端健康、截图操控、控制权、回执核实、升级、归档与手动配置下载。
- 入口：复用原 `AndroidDevicesView.vue`，管理 API 经 `/api/workspaces/:slug/ziwei-connect/terminal/android-devices/*` 由主站后端代理。
- 数据：手机身份、配对、心跳、命令、升级和截图仍保存在原控制服务；主站仅保存已有工作区员工/账号绑定及运行记录。没有第二份手机状态库。
- 权限：沿用主站 Owner/Admin 与工作区成员校验；浏览器不持有原控制台管理员密码，不要求第二次登录。控制服务仅向回环接口提供管理能力。
- 执行链：复用现有 Node 控制服务与 Android Agent/Updater 协议，不重写 MCP，不新建数字员工，不改变本机 daemon。
- 验收：隔离真实 SQLite/HTTP 测试覆盖权限、审批、错误与代理边界；构建后的完整页面通过隔离浏览器夹具覆盖交互；发布后在 `https://qzelynth.top/phone_ai/ziwei-connect` 用主站会话验证真实服务与控制台。
- 安全边界：真实域名验收不批准未知申请、不发送真实设备动作；无真实手机时明确记录装机后尚需验证的端到端流程。
- 发布：先备份两端 SQLite 和服务/网关配置，发布独立版本目录并切换既有主站服务；保留原数据与依赖 symlink、源控制服务及回滚入口。
- 回滚：切回发布前主站版本 symlink 并重启既有主站 API；本轮不迁移或复制手机数据。仅必要时按维护手册恢复 SQLite 备份。
