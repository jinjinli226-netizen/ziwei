# 持久会话双向图片

本次范围由用户明确授权实现、验收及发布。普通持久会话消息仍不创建任务看板卡片；从任务发起的执行可以关联会话。保留已有工作区、员工、设备连接、Creator HOME、维护流程和域名。

用户消息使用现有 Base64 附件结构，支持纯图片与图文。仅接受 PNG、JPEG、GIF、WebP，单次合计不超过 10 MiB。后端先验证图片、执行参数与幂等键，再保存消息与执行；重复提交同一个客户端消息 ID 只产生一条消息和一次执行。

员工输出使用独立 `outputArtifacts` 字段，与用户输入落地信息 `inputAttachments` 分开。Windows 客户端为每次执行建立独立随机输出目录，提示 CLI 将可回传图片放入此目录，并写 `manifest.json`：`{version:1,artifacts:[{path:"result.png",name:"结果.png"}]}`。客户端只读取这次清单明确声明的图片，验证路径归属、真实路径、符号链接、图片魔数与大小，然后转换为平台附件。服务器依据可信 action 的会话归属保存 assistant 附件；不读取浏览器无法访问的本机路径，不扫描电脑寻找图片。

前端按工作区和会话保留草稿，发送和读文件均捕获上下文与修订号。提交过程中切换会话不会串入消息、附件或清空另一条草稿；发送失败保留原消息供重试，并显示具体错误。发送期间阻止同一会话重复提交，服务器幂等键覆盖网络重试。附件展示保留原比例，提供大图预览与真实文件下载，刷新与重新进入会话从已存附件恢复。

Codex 与 Hermes 分别核对原生图片输入能力；无法保证输入支持的运行时组合明确报错，不把文本路径视为识图。实际支持还取决于模型。所有 CLI 输出图片都经同一显式附件通道。

验证包括有意义的后端与客户端回归测试、前端并发测试、真实浏览器桌面及窄屏发送/回图/下载/刷新/失败重试/切会话，以及至少一次真实 Windows CLI 图片输入及图片输出。QA 对象记录精确 ID，最后只清理本次对象。发布前备份，保留旧资源和包，记录提交与源码、静态、官方包 hash；沿既有维护流程更新客户端，避免影响正式连接。

选择清单协议是因为它能明确关联当前执行，适合现有原生 CLI；直接解析 Markdown 本机路径无法可靠下载，扫描工作目录则无法明确归属，因此不采用。此设计没有新自动化、任务看板行为变更或其他审计修复。
