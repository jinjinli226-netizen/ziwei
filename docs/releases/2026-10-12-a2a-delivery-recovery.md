# 2026-10-12 A2A 执行与投递恢复

## 已复现的问题

正式旧消息的服务器 ACK 已提交，Windows 客户端仍在 3 秒内等待回执并报超时。后续 poll 带 `includeAcked=1`，服务器却没有把该字符串视为 true，因此客户端再也没有取得已经 ACK 的动作，CLI 未启动，动作最终 expired。该过期消息保持历史状态，不自动重放。

## 修复行为

- 服务器显式解析 `includeAcked` 布尔查询，并在事务内校验设备、取得动作和提交 ACK。未绑定动作由首次认证设备认领；跨设备操作被拒绝。终态操作仍先验证归属。
- ACK、事件与 result 分别投递。ACK 回执丢失后重试认证 ACK，确认当前状态与租期后才执行。终态 ACK 不启动 CLI。已完成 result 上传失败时，下一次先查询 ACK，再投递同一份持久化结果。
- 执行器在启动前持久化 started；完成后持久化结果。启动后崩溃且没有可确认结果时返回 `EXECUTION_UNCERTAIN`，需要人工核实，避免自动再执行。该路径的完整本地输入和失败证据不会被普通确认保留策略删除。
- 投递目录以工作区、设备、接口地址和动作关联身份校验；输入、完整 result 与轻量进度元数据分文件保存并校验 SHA。确认落盘失败时保持可恢复；确认成功后才清理普通动作的大字节副本。未确认、blocked 和 uncertain 记录不受普通终态清理影响。
- 进度使用持久 event ID，服务器重复接收不重复产生事件。进度通道失败不会阻止终态 result 投递。SQLite 真正 busy/locked 返回可重试 503。
- ACK/result 可请求轻量回执，不重复回传整个图片输入和输出；默认 API 数据与服务器保存的图片字节保持兼容。认证设备可在已完成结果投递前续租；已过期或终态动作不续活。
- poll 与 result 的传输预算各为 600 秒，ACK 与事件各为 15 秒；初始慢 poll 不阻断 heartbeat。每轮只上传一次完整 result，断网后从持久记录继续。
- 会话列表与右侧详情使用同一份已接受的最新执行状态；旧 action/旧选择的晚到响应不能覆盖新执行，expired/cancelled 显示终态。实时重连与轮询均同步两处状态，同一会话的草稿和编辑中的设置保持。
