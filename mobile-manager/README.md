同员工其它聊天的真实在途或未知写入继续阻断，较新的成功回复、不完整摘要、通用 released 标记均不能替代证据。迟到轮询、离开再进入和同名工作区换代均通过回归。只调整 App 的判定，未停止、暂停或升级任何员工，也未发布生产后端或 Windows 改动。全网页476/476和中文组合输入回归通过；准确包的原账号模拟器及交付记录见[本轮验收](../docs/operations/2026-10-19-android-historical-observation-occupancy.md)。

## 0.3 起加入的手机功能

- 聊天首页支持本机置顶和文字草稿，草稿按账号、工作区、员工隔离，重启恢复；只持久化文字与置顶标识，不保存图片、聊天历史或凭据。聊天内查找覆盖当前已加载消息及转发快照，并定位到原消息。
- 聊天页新增员工群组入口。范围是所选负责员工 Bot HOME 内的原生员工协作群：选择已授权伙伴、点选姓名提及、查看分页群记录、查询原请求和成员结果。创建并发送会启动协作，普通成员配置与执行权限仍需原有检查；不提供人类成员聊天、重命名、邀请或跨电脑统一群目录。
- 群记录每次读取 30 条，旧电脑缺少分页回执时明确要求升级；不回退全历史。发送结果未知时保留原请求标识，查询原 action，不自动重发。腐坏或不可读取的本机原请求标识不会被新请求覆盖。
- 工作页新增分类筛选和“记待办”，只保存计划事项，不启动执行。普通创建接口没有跨重启幂等保证；未知回执在当前 App 会话锁定原内容，先到列表核对，同名列表记录不被当成原请求送达证明。
- 最近提醒展示可查看的执行完成、失败及待处理事项。已读仅保存在当前手机，点击先向服务端重新核对原事件权限，再打开原聊天或工作。无群组/@即时通知承诺。
- Android 系统通知由用户主动开启，使用可选通知权限和普通网络状态权限。0.3 的约 15 分钟只读检查在 0.5 保留作补充，持续接收改为自有服务 HTTPS 等待。首次开启跳过旧事件，手机重启后重新打开 App 恢复接收。详见 [原生说明](android/README.md)。

本版继续保留 60 秒 GET 等待上限、原聊天身份、转发和原有管理设置。没有因同步失败自动停止员工、自动重复发送、放开系统浏览器外跳或新增受控手机权限。

## 0.2.2 一分钟读取等待

按用户要求，GET 读取等待上限从 20 秒改为 60 秒，慢请求可继续收取完整结果。真实网络、权限、内容读取错误仍显示；一分钟后仍未完成会明确提示超时。页面同步失败不会停止员工任务，任务仅通过已有停止入口显式请求停止。离页或后台仍取消过期只读请求；发送、转发、保存等写入不增加超时取消或自动重试。此时限在 App 资产中，需要覆盖升级本包生效；服务端运行记录图片减负可独立对旧版本生效。

## 0.2.1 同步连接与缓存

离开员工或切入后台时取消该员工尚未完成的只读请求，释放连接；恢复后重新读取原聊天。发送、转发、保存等已发出的操作保留原回执处理，不随页面取消，也不自动重发。聊天条件缓存按最近使用顺序保留，仍有总容量和条目限制，每次都经服务器认证及 ETag 校验。

## 0.2.0 聊天首页与记录转发

默认首页为最近聊天，底部为聊天、员工、工作、我的；设备互联移入我的。会话索引复用服务端员工与原主聊天 ID，显示最近消息预览和当前用户真实未读。已读只提交当前屏幕显示的消息 ID；打开转发或图片、退到后台都不会把未看到的新消息自动标为已读。已读水位不改聊天更新时间、不派发工作，也不清空大型历史的条件读取缓存。

聊天里长按文字消息或点击消息操作，可转发单条或多选最多20条，填写附言并选择另一位员工。默认“仅转发记录”保存服务端原文、图片、发送者与时间快照；“转发并请他处理”须明确选择。目标聊天中的记录卡片可以在 App 内展开和查看原图，源聊天草稿保留。服务端检查来源与目标权限并原子保存；没有收到回执时只能显式重试同一标识，后续权限变化或接口回滚不能被当成原请求未送达。本机只保留请求哈希和 ID，不持久化转发正文。

本版需要共享后端的聊天转发、最近会话与已读接口；网页同步显示同一转发记录。

## 首版功能

- 员工首页：原员工头像、名称、岗位及服务器返回的运行状态，直接打开原聊天。
- 长期聊天：文字、多图、真实执行进度；已初始化 Bot 可提交既有停止请求，待电脑返回退出证据后才显示已停止。
- 听汇报：选择员工并排序 → 当前员工汇报 → 追问 → 下一位或稍后再听 → 汇总与计划待办。任务和执行记录是事实来源，没有记录明确显示暂无记录。汇报及追问保留在员工原聊天，本机只保存本次会次和顺序。
- 工作：原任务列表、说明编辑及合法状态流转；汇报中明确的下一步可经点击加入计划任务，创建本身不启动执行。
- 员工详情：名称、描述、头像编辑，模型与能力配置，以及现有 Bot 例行工作的添加、暂停、恢复和立即运行。
- 设备互联：沿用原 Owner/Admin 终端权限，查看电脑和手机状态、最后截图与拍摄时间、显式请求新截图和放大查看。可在 App 内进行电脑配对、手机入网审批与员工关联；普通成员不会取得终端管理员权限。

## 数据和恢复

本地 WebView 仅拦截 `https://qzelynth.top/__ziwei_manager__/` 下打包的界面资源。`/api/` 通过原站点的 HTTPS、HttpOnly 会话 Cookie 和原权限检查访问，账号、员工、Profile/HOME、任务、会话及手机队列均沿用原系统，不需要替换正式站或迁移数据库。

前台每 8 秒及回到前台时重新读取状态；后台不执行员工任务或保持另一个调度器。普通消息的请求标识及内容摘要按账号、工作区、员工保存，断线重试保持同一 `clientMessageId`。汇报页按原执行 ID 关联回执；旧接口只暴露最新执行时，以相同消息标识和原消息体取回服务端幂等回执，不生成另一个执行。图片字节以原聊天为准，本机会次仅持久化附件元数据。

汇报顺序目前仅保存在这台管理手机；换手机不会自动同步会次。退出 App 后恢复当前会次，不能保证系统清除应用数据后的恢复。设备离线、原执行待核实、配置或权限冲突均显示真实错误，不自动启用员工、重建 Profile 或改用其他设备。

## 开发和构建

结构：`web/` 为独立移动界面 ES modules，`android/` 为 Java 原生外壳，`scripts/` 为固定工具链手工构建脚本。自建通知版本不使用 Gradle 或任何第三方消息 SDK。`web/bot-presentation.js` 复用本次桌面版本的真实停止和执行状态规则，变更状态合同时应同步核对该模块。

```sh
node --test mobile-manager/test/*.test.mjs
node mobile-manager/test/browser-check.mjs
node mobile-manager/test/browser-history-check.mjs
node mobile-manager/test/browser-settings-check.mjs
node mobile-manager/test/browser-forwarding-check.mjs
python3 mobile-manager/scripts/build-android.py
```

构建使用缓存内的固定 JDK、Android API 35 与 build-tools 35；脚本校验工具来源、APK 签名、zipalign、包名、版本和打包资源。输出在被 Git 忽略的 `mobile-manager/dist/`，`manifest.json` 记录源码提交和每个界面资源哈希。内部签名密钥留在本机私有缓存，不提交到 Git，不打入 APK。
